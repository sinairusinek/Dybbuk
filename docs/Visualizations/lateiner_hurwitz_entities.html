Node id conventions

Ids are kind:slug. A slug is a database id where the entity has one, the catalogue key where the catalogue supplies one, and a normalised name where neither does — so an id is stable only as far as its source is.

kindexample id
personperson:dbid683
workwork:3787
editionedition:MishkeMashke-Kultur1910
songsong:1
eventevent:3838-04031889-poolestheatre
orgorg:poolestheatre
placeplace:warsaw

How to read a row. A blue edge is a confirmed link carrying a database id. An amber edge is an automatic proposal — order-insensitive token matching, which is what the catalogue's “Surname, Given” against people_db's “Given Surname” requires — and it is a suggestion, not a decision. A red edge is an open question: no candidate, several equally good ones, or a match too weak to trust.
